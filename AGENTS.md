# Project Instructions

- Never read, print, expose, or modify `.env`, `.env.local`, `.env.*`, or other files containing secrets, credentials, API keys, passwords, tokens, or private keys.
- Never expose secret values in responses.
- Do not install packages without my approval.
- Do not modify database schema or run migrations without my approval.
- Do not delete files without my approval.
- Do not modify deployment configuration without my approval.
- Do not make unrelated changes.
- Inspect existing code and patterns before implementing changes.
- Keep changes minimal and focused on the requested task.
- For significant changes, explain the proposed approach before implementation.
- After implementation, run appropriate type checks and tests.
- Report all files changed and explain why each was changed.
- Never assume an architectural change is necessary just because it is possible.
- Treat payment, inventory, authentication, authorization, and order-management code as sensitive areas requiring extra care.
